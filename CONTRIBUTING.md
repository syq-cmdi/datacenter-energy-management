# Contributing

Power-to-Chip v0.1 is seeking technical criticism, not endorsements.

Start with one case in the [Constraint Atlas](CONSTRAINT_ATLAS.md), or propose a
new synthetic pattern when the current atlas misses the interface you need to
challenge.

## Good validation feedback

Open one issue for one gate or failure mode. Include:

- the Constraint Atlas case ID, when applicable;
- assessment dimension and question;
- project stage where the issue becomes critical;
- why the current wording could create false confidence;
- the propagation path or project decision that changes if the gate is wrong;
- a proposed correction;
- a current primary source or a fully sanitized field example, when available.

## Safety and confidentiality

Do not submit customer names, facility locations, asset identifiers, drawings,
one-line diagrams, credentials, security configurations, proprietary vendor
data or other sensitive project information. Synthetic examples are preferred.

Do not present feedback as professional approval of a real project. Do not use
this repository to request or exchange book purchases, Kindle Unlimited
reading, reviews, testimonials, stars or endorsements.

## Evidence standard

Prefer current manufacturer requirements, applicable codes and standards, and
primary material from recognized technical organizations. Clearly separate a
source-backed statement from an engineering judgment or proposed heuristic.

## Review criteria

A change should make the tool:

- less likely to create false confidence;
- more explicit about assessment boundaries;
- clearer about evidence and ownership;
- more useful across electrical, mechanical, controls, commissioning and
  operations teams; and
- no more invasive with respect to facility data.
